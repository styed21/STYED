# Contact page and donation button

The Contact page at `contact.html` is a React/TypeScript route included in the Vite production build and prerenderer. Navigation, footer links, and mentorship/partnership calls to action point to it. The existing `get-involved.html#contact` section remains as a link to the new page so previous links still resolve.

The supplied HopeWorks image informs the layout only: a merged photo banner, two-column form/contact area, map, and volunteer callout. Copy, colors, logo, typefaces, and photographs come from STYED's existing site. The banner uses `hero-mentorship.webp` and the callout uses `together.webp`. Scoped GSAP entrances and photo parallax honor reduced motion; the page does not introduce looping animation or playback controls.

Files:

- `src/pages/Contact.tsx`: page structure, hero motion, community map and contact area.
- `src/components/ContactForm.tsx`: required-field/email validation, preview, copy, and edit controls.
- `src/data/contact.ts`: public contact details and supported inquiry subjects.
- `src/contact.css`: scoped desktop, tablet, and mobile styles.
- `src/components/DonateButton.tsx` and `src/donate-button.css`: reusable rounded red gradient donation link with an inline vector heart-in-hands icon, divider, and chevron. Used in the shared header and home donation section.

## Contact information and delivery

The PRD explicitly leaves public email, phone, office address, and hours unspecified. The account email in its hosting section is private and is not used. `contactDetails` contains null values for unconfirmed public fields. Setting these values updates their display but does not enable message delivery.

The form is clearly labeled as a preview. Required fields are name, email, subject, and message; phone is optional. Whitespace-only names/messages are rejected. Form data stays in React state and is not submitted, persisted, or logged. Copy writes to the clipboard only on a visitor's click, with a fallback notice if clipboard access fails. A reload clears entered values. The fieldset is disabled before hydration to prevent a native GET submission when JavaScript is unavailable. No payment or contact request is generated by this page.

Mentorship and partnership links use `?topic=mentor#message` and `?topic=partner#message`; only known subjects are accepted. The production output checker handles query strings when validating their local route and anchor.

Before enabling real inquiries, connect a verified recipient and delivery service with server-side validation, abuse controls, and real pending/success/error handling. Update the visible preview wording only when delivery works.

## Map

The lazy-loaded [OpenStreetMap](https://www.openstreetmap.org/#map=11/44.98/-93.19) iframe shows the Twin Cities area. It deliberately has no office marker because no office address has been supplied. The iframe retains its provider's controls and [attribution](https://www.openstreetmap.org/copyright). The external map link remains available if the embed cannot load. This public regional map is the page's external content dependency; the supplied photos and fonts are local.

## Verification

Production checks validate six prerendered pages, one main heading per page, unique IDs, and local routes/assets. Browser QA covers desktop (1440px), tablet (843px), mobile (390px and 320px), a non-overlapping 44px-minimum mobile donation button, the seven-link mobile menu, active Contact navigation, loaded map/photo content, required-field and email validation, preview and preserved values when editing, subject-prefilled incoming links, reduced motion, and donation navigation. The clipboard success handler is checked with a browser-local clipboard stub so testing does not overwrite the user's clipboard. The page produced no browser runtime errors in these checks.

`.cache/before-contact-page/` preserves the modified integration files from before this addition. Original reference materials in `STYED/` are unchanged.
